La consigna pedía un CRUD con TDD en tres lenguajes distintos, ninguno Java ni Kotlin, y al menos uno con framework de front. Se hicieron seis. Lo interesante no es el CRUD: es lo que cada lenguaje te deja y no te deja escribir en un test.

De qué trata el ejercicio

Una entidad con reglas, un repositorio en memoria, y un test por cada regla

Las seis implementaciones resuelven exactamente lo mismo. Esa repetición es deliberada: al fijar el problema, lo único que varía entre proyectos es el lenguaje, y ahí se ve qué aporta cada uno.

1Entidad validada

Campos obligatorios y rango de año. Un solo lugar donde viven las reglas.

2CRUD completo

Crear, obtener por id, listar, actualizar parcial y eliminar.

3Ids del repositorio

Autoincrementales, asignados por el repositorio y no por quien llama.

4Dos clases de error

Datos inválidos y entidad no encontrada, siempre distinguibles en el test.

El ciclo, con salidas reales

RED → GREEN, en Go

Las dos terminales de abajo son corridas reales de go test. La primera es el estado RED: el test de validación ya existe, pero NuevaPelicula todavía no rechaza el título vacío. La segunda es después de agregar esas cuatro líneas.

RED el test falla porque el código aún no existe
Fijate que solo falla la fila titulo_vacio de la tabla: las otras cuatro pasan. Eso es lo que dan los subtests — la falla apunta al caso exacto.
GREEN el mínimo código que lo hace pasar
Se agrega la guarda del título en el constructor. Nada más: lo elegante viene después, en REFACTOR, ya con la red del test puesta.

La conclusión

Tres formas de probar que algo falló

Mismo caso de prueba en los seis proyectos —pedir un id que no existe— y tres posturas distintas. Es el mejor resumen de por qué repetir el ejercicio valió la pena.

1 · Excepciones

C#, Python, PHP, React

with pytest.raises(ViniloNoEncontradoError):
    repositorio.obtener_por_id(999)
El error viaja por un canal aparte del valor de retorno, así que el test necesita un mecanismo especial para capturarlo.

2 · Valor, verificado por el compilador

Rust

let resultado = repositorio.obtener_por_id(999);
assert_eq!(resultado, Err(ErrorCatalogo::VideojuegoNoEncontrado(999)));
El error es el resultado. Se compara con la misma aserción que el caso feliz, y el compilador no te deja ignorarlo.

3 · Valor, verificado por convención

Go

_, err := repositorio.ObtenerPorID(999)

if !errors.Is(err, catalogo.ErrNoEncontrada) {
    t.Errorf("se esperaba ErrNoEncontrada, se obtuvo: %v", err)
}
También es un valor, pero repositorio.Eliminar(id) a secas compila igual. Acá el test es la única red.
